# Support

## Getting help

- **A finding you do not understand**: `sqs.py explain <CODE>` prints why the rule exists
  and how to fix what it found. All rules are on the
  [quality rules page](https://letsloose501.github.io/sqs-skills/quality-rules).
- **A false positive, a bug, a harness whose documentation changed**:
  [open an issue](https://github.com/letsloose501/sqs-skills/issues) with the command you
  ran and its output. A finding on a real skill you can share is the most useful report
  there is: every rule here was narrowed that way.
- **A security problem in the suite itself**: see [SECURITY.md](SECURITY.md).

This is one person's project. There is no SLA, and issues are read.

## Supporting the project

SQS takes no money. What helps:

- a star on [GitHub](https://github.com/letsloose501/sqs-skills), which is how other
  people find it;
- telling people who write skills that it exists;
- an issue with a real skill it got wrong;
- a pull request - see [CONTRIBUTING.md](CONTRIBUTING.md).

If you ship something built on SQS, keep the NOTICE file with it and name the project -
the licence asks for it, and it is how the next person finds the source.
